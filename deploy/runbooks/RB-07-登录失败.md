# RB-07 登录失败 Runbook

> 适用: sa-token 校验失败、租户隔离异常、密码错误激增、认证服务异常
> 优先级: P1 | 影响: 用户无法登录、安全风险 | 设计来源: 33/63

## 1. 现象

- `/api/v1/auth/login` 返回 500 / 401 / 403。
- 大量用户报告"刚刚还能用，突然被踢出"。
- 应用日志出现 `NotLoginException` / `LoginException` / `TenantIsolationException`。
- sa-token 键在 Redis 中突然消失或 TTL 异常。
- 密码错误日志激增（可能是暴力破解）。
- 单点登录回跳失败或 token 解析错误。

## 2. 影响范围

- 全站需要登录的接口全部 401，业务停摆。
- 移动端、Web 端、第三方集成全部受影响。
- 若为暴力破解，可能引发安全事件。
- 若为租户隔离异常，可能引发数据越权（更严重）。

## 3. 快速判断命令

```bash
# 1) 应用与 Redis 状态
docker ps --filter "name=yutong-boot" --filter "name=yutong-redis" --format "{{.Names}}\t{{.Status}}"
curl.exe -s http://localhost:20010/actuator/health | python -m json.tool

# 2) Redis sa-token 键检查
docker exec yutong-redis redis-cli -p 6379 KEYS "satoken:*" | findstr /c:"satoken:" /v
docker exec yutong-redis redis-cli -p 6379 DBSIZE
docker exec yutong-redis redis-cli -p 6379 TTL "satoken:login:session:default"

# 3) 登录接口冒烟
curl.exe -s -X POST http://localhost:20010/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"wrong","tenantId":"default"}' \
  -w "\nHTTP: %{http_code}\n"

# 4) 最近登录失败日志
docker exec yutong-postgres psql -U yutong -d yutong -c "
select user_id, username, tenant_id, login_type, status,
       left(error_message, 200) as err, ip, created_time
from sys_login_log
where status != 'SUCCESS'
  and created_time > now() - interval '1 hour'
order by created_time desc
limit 30;"

# 5) 暴力破解检测（同 IP 多次失败）
docker exec yutong-postgres psql -U yutong -d yutong -c "
select ip, count(*) as fail_count,
       count(distinct username) as tried_users,
       max(created_time) as latest
from sys_login_log
where status != 'SUCCESS'
  and created_time > now() - interval '15 minutes'
group by ip
having count(*) > 5
order by fail_count desc;"

# 6) sa-token 配置
curl.exe -s http://localhost:20010/actuator/configprops | python -m json.tool | findstr -i "satoken"

# 7) Redis 连接数与内存
docker exec yutong-redis redis-cli -p 6379 INFO clients | findstr "connected_clients"
docker exec yutong-redis redis-cli -p 6379 INFO memory | findstr "used_memory_human"
```

## 4. 关键日志位置

| 位置 | 内容 |
| --- | --- |
| `docker logs yutong-boot` | sa-token 异常、认证过滤器栈 |
| `docker logs yutong-redis` | Redis 内存/连接/淘汰策略 |
| `sys_login_log` 表 | 登录历史、IP、错误信息 |
| `sys_user` 表 | 用户状态（是否被锁定） |
| Redis `satoken:*` 键 | 会话、token、权限缓存 |

## 5. 回滚或临时降级方案

### 5.1 Redis 恢复（如 Redis 宕机导致）

```bash
# 1) 恢复 Redis（见 RB-03）
docker restart yutong-redis
sleep 10
docker exec yutong-redis redis-cli -p 6379 PING

# 2) 重启应用，让 sa-token 重新初始化
docker restart yutong-boot
sleep 30

# 3) 用户需要重新登录（会话已丢失）
```

### 5.2 sa-token 配置回滚（如配置变更引起）

```bash
# 1) 备份当前配置
cp backend/yutong-boot/src/main/resources/application.yml application.yml.broken

# 2) 从 Git 恢复上一版本
git log --oneline -5 -- backend/yutong-boot/src/main/resources/application.yml
git checkout {prev_commit} -- backend/yutong-boot/src/main/resources/application.yml

# 3) 重新构建启动
cd backend && mvn clean package -pl yutong-boot -am -DskipTests
docker restart yutong-boot
```

### 5.3 用户解锁（如被暴力破解保护误锁）

```sql
-- 1) 查看被锁定的用户
select id, username, status, locked_until, left(login_fail_reason, 200) as reason
from sys_user
where status = 'LOCKED'
   or locked_until > now();

-- 2) 解锁（须 Incident Commander + 安全支持确认）
update sys_user
set status = 'ACTIVE',
    locked_until = null,
    login_fail_count = 0,
    login_fail_reason = null
where id in ('{userId1}', '{userId2}');

-- 3) 清理 Redis 中的失败计数
docker exec yutong-redis redis-cli -p 6379 DEL "login_fail:{userId}"
```

### 5.4 紧急封禁恶意 IP

```sql
-- 1) 加入黑名单
insert into sys_ip_blacklist (id, ip, reason, expire_time, created_by)
values (gen_ulid(), '{malicious_ip}', '暴力破解: 15min 内 N 次失败',
        now() + interval '24 hours', 'incident_commander');

-- 2) 立即生效（如有 IP 过滤器）
docker restart yutong-boot
```

### 5.5 临时关闭多因素/强制降级到密码登录

```yaml
# application.yml 紧急配置
yutong:
  auth:
    mfa-required: false          # 临时关闭 MFA
    captcha-required: false      # 临时关闭验证码（仅在排查时）
    lockout-threshold: 10        # 锁定阈值放宽（从 5 调到 10）
    lockout-duration-minutes: 15 # 锁定时长缩短
```
