# RB-10: 监控指标采集失败

> 设计来源: 62-可观测性指标日志链路详设、63-生产部署运维 Runbook 详设、91-Web 基础后台逐页交互详设
> 关联组件: MonitorController / MeterRegistry / Actuator / Prometheus
> 告警: JvmHeapUsageHigh / HikariPoolNearExhaustion / ApplicationDown

## 现象

- 前端「性能指标监控」页面所有卡片显示「-」，图表空白
- 前端「服务健康」页面某些组件状态为 DOWN 或检查耗时异常高
- Prometheus 靶点 `yutong-boot` 显示 DOWN，Grafana 看板无数据
- `/actuator/prometheus` 端点返回 404 或空响应

## 排查步骤

### 1. 确认 Actuator 端点可用性

```bash
curl -s http://localhost:20010/actuator/health | jq .
curl -s http://localhost:20010/actuator/prometheus | head -n 20
```

若返回 404：
- 检查 `application.yml` 中 `management.endpoints.web.exposure.include` 是否包含 `health,prometheus`
- 确认 `yutong-boot` 模块引入了 `micrometer-registry-prometheus` 依赖

### 2. 检查 Micrometer 指标注册

进入后端日志，搜索：
```
MeterRegistry
HistogramSnapshot
jvm.memory.used
```

若 `MeterRegistry` 为 null（MonitorController 中 `@Autowired(required = false)`），则：
- 检查 `yutong-boot/pom.xml` 是否包含 `spring-boot-starter-actuator`
- 检查启动日志是否有 `meterRegistry` bean 初始化成功

### 3. 检查 MonitorController 权限拦截

```bash
curl -s http://localhost:20010/api/v1/monitor/metrics \
  -H "Authorization: Bearer ${TOKEN}" | jq .
```

若返回 403：
- 确认当前用户拥有 `monitor:metrics:view` 权限码
- 检查 `RequiresPermission` 拦截器是否正常工作

### 4. 检查 Prometheus 抓取配置

```bash
curl -s http://localhost:20090/api/v1/targets | jq '.data.activeTargets[] | select(.labels.job=="yutong-boot")'
```

关注：
- `health`: up / down
- `lastError`: 若显示 `connection refused`，检查防火墙或容器网络
- `lastScrapeDuration`: 若 > 10s，可能端点响应过慢

### 5. 检查数据库连接池指标来源

连接池指标来自 HikariCP Micrometer 集成。确认：
```yaml
# application.yml
spring:
  datasource:
    hikari:
      register-mbeans: true
      metrics-tracker-factory: com.zaxxer.hikari.metrics.micrometer.MicrometerMetricsTrackerFactory
```

若使用非 Hikari 连接池，需在 MonitorController 中适配对应 MXBean。

### 6. 检查 JVM 指标缺失

若缺失 `jvm_memory_used_bytes` 等指标：
- 确认启动参数无 `-XX:+DisableAttachMechanism`（可能阻止 JMX）
- 确认 JVM 版本 >= 17（Micrometer 对旧版 JVM 支持有限）

## 常见原因与修复

| 原因 | 修复方案 |
|------|---------|
| Actuator 端点未暴露 | 修改 `application.yml` 添加 `management.endpoints.web.exposure.include: health,info,prometheus,metrics` |
| Prometheus 依赖缺失 | 在 `yutong-boot/pom.xml` 添加 `micrometer-registry-prometheus` |
| Micrometer 版本不兼容 | 统一 Micrometer 版本至 1.13.x，与 Spring Boot 4.0.2 兼容 |
| HikariCP 指标未注册 | 开启 `register-mbeans: true`，重启应用 |
| 权限拦截导致前端无数据 | 为监控管理员分配 `monitor:metrics:view` 和 `monitor:health:view` 权限 |
| Prometheus 网络不可达 | 检查 docker-compose 网络配置，确保 prometheus 容器能访问 backend:20010/actuator/prometheus |

## 回滚

若修改配置后应用无法启动：
1. 回滚 `application.yml` 变更
2. 若使用 Git，执行 `git checkout -- deploy/docker-compose.boot.yml backend/yutong-boot/src/main/resources/application.yml`
3. 重启容器：`docker compose -f deploy/docker-compose.boot.yml restart`

## 验证

修复后，依次验证：
1. `curl http://localhost:20010/actuator/health` 返回 `{"status":"UP"}`
2. `curl http://localhost:20010/actuator/prometheus | grep jvm_memory_used_bytes` 有输出
3. `curl http://localhost:20010/api/v1/monitor/metrics` 返回完整 JSON（含 jvmHeapUsed、dbPoolActive、httpP95）
4. 前端「性能指标监控」页面 10 秒内加载出数据，图表正常渲染
5. Prometheus Targets 页面 `yutong-boot` 状态为 UP
