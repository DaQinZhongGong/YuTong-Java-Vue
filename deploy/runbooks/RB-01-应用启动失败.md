# RB-01 应用启动失败 Runbook

> 适用: yutong-boot 容器无法启动、Spring Boot 启动异常退出
> 优先级: P0 | 影响: 全站不可用 | 设计来源: 33/63

## 1. 现象

- 容器 `yutong-boot` 状态为 `Exited` 或反复 `Restarting`。
- `docker logs yutong-boot` 含 `APPLICATION FAILED TO START` / `BeanCreationException` / `BindException`。
- `/actuator/health` 503 或连接拒绝。
- 启动日志出现 `FlywayException` / `DataSource lookup failed` / `RedisConnectionFailureException`。

## 2. 影响范围

- 全站 API 不可用（登录、字典、申请单、AI、低代码生成）。
- 前端 web-admin 调用 API 全部 5xx。
- 移动端无法登录。
- 若有定时任务，会停止执行。

## 3. 快速判断命令

```bash
# 1) 查看容器状态
docker ps -a --filter "name=yutong-boot" --format "{{.Names}}\t{{.Status}}\t{{.Ports}}"

# 2) 查看最近 200 行启动日志
docker logs --tail 200 yutong-boot 2>&1 | grep -E "ERROR|FAILED|Exception|Caused by"

# 3) 健康检查
curl.exe -s -o NUL -w "%{http_code}\n" http://localhost:20010/actuator/health

# 4) 端口占用检查（Windows）
netstat -ano | findstr :20010

# 5) 确认依赖容器
docker ps --filter "name=yutong-postgres" --filter "name=yutong-redis" --filter "name=yutong-minio" --format "{{.Names}}\t{{.Status}}"
```

## 4. 关键日志位置

| 位置 | 内容 |
| --- | --- |
| `docker logs yutong-boot` | Spring Boot 启动日志、异常栈 |
| `backend/yutong-boot/logs/` | 应用日志文件（如挂载） |
| `release-evidence/{version}/smoke-test.txt` | 上次冒烟测试基线 |

## 5. 回滚或临时降级方案

### 5.1 应用回滚（首选）

```bash
# 1) 停止失败容器
docker stop yutong-boot && docker rm yutong-boot

# 2) 拉取上一版本镜像（替换 {prev_version}）
docker pull yutong-boot:{prev_version}

# 3) 启动上一版本（使用相同网络和配置）
docker run -d --name yutong-boot \
  --network yutong-net \
  -p 20010:8080 \
  -e SPRING_PROFILES_ACTIVE=default \
  -e SPRING_DATASOURCE_URL=jdbc:postgresql://yutong-postgres:5432/yutong \
  -e SPRING_DATA_REDIS_HOST=yutong-redis \
  yutong-boot:{prev_version}

# 4) 等待 30s 后健康检查
sleep 30
curl.exe -s http://localhost:20010/actuator/health
```

### 5.2 配置回滚（如由配置变更引起）

```bash
# 1) 备份当前配置
cp backend/yutong-boot/src/main/resources/application.yml application.yml.broken

# 2) 从 Git 恢复上一版本配置
git log --oneline -5 -- backend/yutong-boot/src/main/resources/application.yml
git checkout {prev_commit} -- backend/yutong-boot/src/main/resources/application.yml

# 3) 重新构建并启动
cd backend && mvn clean package -pl yutong-boot -am -DskipTests
docker restart yutong-boot
```

### 5.3 临时降级（如 AI 模块启动失败）

在 application.yml 中关闭非核心模块：

```yaml
yutong:
  ai:
    degraded: true
    disabledTools: [generate_page_draft, generate_sql_draft]
  lowcode:
    generatorEnabled: false
```

## 7. 后续修复任务

1. 在 CI 流水线增加启动冒烟检查（`ci.yml` 的 backend job 末尾启动一次 boot 并校验 /actuator/health）。
2. 把失败配置项加入 `feature-flags.yaml` 的 safeDefault 校验。
3. 更新本 Runbook，补充本次故障的特殊判断命令。
