# RB-08: 插件安装失败

> 设计来源: 45-插件与模板生态设计、63-生产部署运维 Runbook 详设
> 关联组件: PluginController / PluginApplicationService / PluginPackage / PluginInstallation
> 告警: 暂无独立告警，依赖业务错误码或用户反馈

## 现象

- 前端插件市场点击「安装」后，依赖校验弹窗提示版本不兼容或缺少依赖
- 安装请求返回 4xx/5xx 错误，或长时间无响应
- 安装后插件状态未变为「已启用」，或系统功能异常

## 排查步骤

### 1. 确认错误码与响应

调用接口：
```bash
curl -s "http://localhost:20010/api/v1/plugins/${PLUGIN_ID}/dependency-check" \
  -H "Authorization: Bearer ${TOKEN}"
```

关注字段：
- `versionCompatible`: false 表示平台版本不兼容
- `missingDependencies`: 列出缺少的依赖插件编码
- `riskLevel`: HIGH 表示高风险插件，可能触发安全策略拦截

### 2. 检查平台版本兼容性

插件的 `minPlatformVersion` / `maxPlatformVersion` 必须与当前平台版本（`1.0.0-GA2`）匹配。
查看当前平台版本：
```bash
curl -s http://localhost:20010/api/v1/monitor/health | jq '.data.version'
```

### 3. 检查依赖链完整性

如果插件 A 依赖插件 B，插件 B 依赖插件 C，必须确保整条依赖链都已安装且处于 ACTIVE 状态。
```sql
SELECT plugin_code, status FROM plugin_installation WHERE status = 'ACTIVE';
```

### 4. 检查数据库锁与并发

安装操作使用 `@Transactional`，高并发下可能出现锁等待。
```sql
SELECT * FROM pg_locks WHERE relation = 'plugin_installation'::regclass;
```

### 5. 查看审计日志

```bash
curl -s "http://localhost:20010/api/v1/plugins/audit-logs?pluginCode=${CODE}&pageNo=1&pageSize=5" \
  -H "Authorization: Bearer ${TOKEN}"
```

## 常见原因与修复

| 原因 | 修复方案 |
|------|---------|
| 平台版本不兼容 | 升级平台或联系插件提供方更新兼容版本 |
| 缺少依赖插件 | 先安装缺失的依赖插件，再重新安装目标插件 |
| 插件包哈希校验失败 | 重新上传插件包，确认签名状态为 SIGNED |
| 数据库连接池耗尽 | 参照 RB-02 扩容连接池或降低并发安装压力 |
| 插件代码抛出初始化异常 | 查看后端日志，定位具体 Bean 初始化错误，禁用该插件后修复代码 |

## 回滚

若安装后系统异常，立即调用禁用接口：
```bash
curl -X POST "http://localhost:20010/api/v1/plugins/${ID}/disable" \
  -H "Authorization: Bearer ${TOKEN}"
```

必要时卸载：
```bash
curl -X POST "http://localhost:20010/api/v1/plugins/${ID}/uninstall" \
  -H "Authorization: Bearer ${TOKEN}"
```

## 验证

禁用/卸载后，确认：
1. 服务健康检查 `/actuator/health` 返回 UP
2. 前端插件市场列表刷新后状态正确
3. 系统核心功能（登录、合同查询、报表）正常
