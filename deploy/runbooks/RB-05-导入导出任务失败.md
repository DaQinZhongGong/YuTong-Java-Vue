# RB-05 导入导出任务失败 Runbook

> 适用: Excel 导入失败、导出超时、异步任务积压、死信
> 优先级: P2 | 影响: 批量数据操作 | 设计来源: 33/63

## 1. 现象

- `/api/v1/imports` / `/api/v1/exports` 接口返回 500 或长时间 pending。
- 任务状态长期为 `RUNNING` 超过 SLA 阈值（默认 30 分钟）。
- 应用日志出现 `ExcelProcessingException` / `OutOfMemoryError` / `TaskTimeoutException`。
- 任务表 `imp_exp_task` 中 `status = FAILED` 数量激增。
- 导入数据部分成功部分失败，出现孤儿数据。

## 2. 影响范围

- 批量用户/字典/申请单导入阻塞，运营效率下降。
- 大数据量导出失败，影响报表交付。
- 长时间任务占用数据库连接，可能级联影响在线请求。
- 死信任务堆积，占用存储。

## 3. 快速判断命令

```bash
# 1) 应用容器状态
docker ps --filter "name=yutong-boot" --format "{{.Names}}\t{{.Status}}"

# 2) JVM 内存（导出大文件易 OOM）
curl.exe -s "http://localhost:20010/actuator/metrics/jvm.memory.used?tag=area:heap" | python -m json.tool
curl.exe -s "http://localhost:20010/actuator/metrics/jvm.memory.max?tag=area:heap" | python -m json.tool

# 3) 任务表统计
docker exec yutong-postgres psql -U yutong -d yutong -c "
select status, count(*), max(created_time) as latest
from imp_exp_task
where created_time > now() - interval '24 hours'
group by status
order by status;"

# 4) 长时间运行任务
docker exec yutong-postgres psql -U yutong -d yutong -c "
select id, task_no, task_type, status,
       now() - started_time as duration,
       left(error_message, 200) as err
from imp_exp_task
where status = 'RUNNING'
  and started_time < now() - interval '30 minutes'
order by started_time;"

# 5) 失败任务 TOP 20
docker exec yutong-postgres psql -U yutong -d yutong -c "
select id, task_no, task_type, status, error_message,
       finished_time - started_time as duration
from imp_exp_task
where status = 'FAILED'
  and created_time > now() - interval '24 hours'
order by finished_time desc
limit 20;"

# 6) 数据库连接占用
docker exec yutong-postgres psql -U yutong -d yutong -c "
select state, count(*)
from pg_stat_activity
where datname = 'yutong'
group by state;"

# 7) 任务相关接口错误率
curl.exe -s "http://localhost:20010/actuator/metrics/http.server.requests?tag=uri:/api/v1/imports&tag=status:500" | python -m json.tool
```

## 4. 关键日志位置

| 位置 | 内容 |
| --- | --- |
| `docker logs yutong-boot` | 任务异常栈、OOM、超时 |
| `imp_exp_task` 表 | 任务状态、错误信息、耗时 |

## 5. 回滚或临时降级方案

### 5.1 取消长时间运行任务

```sql
-- 1) 标记长时间任务为 CANCELLED（须 Incident Commander 确认）
update imp_exp_task
set status = 'CANCELLED',
    error_message = 'MANUAL CANCEL: timeout > 30min',
    finished_time = now()
where status = 'RUNNING'
  and started_time < now() - interval '30 minutes';

-- 2) 释放相关数据库连接（如还残留）
select pg_terminate_backend(pid)
from pg_stat_activity
where datname = 'yutong'
  and application_name like '%import-export%'
  and state = 'idle in transaction';
```

### 5.2 数据前向补偿（导入部分成功）

```sql
-- 1) 查询已成功导入的行
select count(*) from imp_exp_task_detail
where task_id = '{taskId}' and status = 'SUCCESS';

-- 2) 查询失败行明细
select row_no, row_data, error_message
from imp_exp_task_detail
where task_id = '{taskId}' and status = 'FAILED'
order by row_no
limit 100;

-- 3) 若需回滚已导入数据（谨慎，业务确认后执行）
-- 通常采用前向补偿: 修正失败行后重新导入，不回滚成功行
```

### 5.3 临时降级（导出 OOM）

```yaml
# application.yml 紧急配置
yutong:
  task:
    export:
      max-rows: 10000         # 单次导出最大行数（从 100000 降）
      streaming: true          # 启用流式导出
      timeout-minutes: 10      # 超时时间（从 30 降）
    import:
      batch-size: 200          # 批处理大小（从 1000 降）
      max-rows: 5000
```

```bash
# JVM 堆临时扩容
docker stop yutong-boot
docker run -d --name yutong-boot \
  -e JAVA_OPTS="-Xmx2g -Xms1g" \
  ...其他参数...
  yutong-boot:0.5.0
```

### 5.4 死信任务清理

```sql
-- 1) 备份死信任务
copy (select * from imp_exp_task where status = 'FAILED' and created_time < now() - interval '7 days')
to '/tmp/dead_tasks.csv' with csv header;

-- 2) 归档后清理
delete from imp_exp_task
where status = 'FAILED'
  and created_time < now() - interval '30 days';
```
