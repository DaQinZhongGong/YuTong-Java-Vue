# RB-02 数据库连接失败 Runbook

> 适用: PostgreSQL 不可达、连接池耗尽、Flyway 迁移失败
> 优先级: P0 | 影响: 全站持久化失败 | 设计来源: 33/63

## 1. 现象

- `/actuator/health` 返回 `{"db":{"status":"DOWN"}}`。
- 应用日志出现 `Cannot get a connection, pool error` / `Connection refused` / `FATAL: password authentication failed`。
- Flyway 启动报 `FlywayException` / `Validate failed` / `Detected resolved migration not applied to database`。
- 接口大量 500，错误码 `DB_CONN_ERROR` / `DB_TIMEOUT`。
- Grafana `HighErrorRate5xx` 告警触发。

## 2. 影响范围

- 全站写入失败（登录、提交申请单、AI 对话历史、低代码生成任务）。
- 读取类接口可能因缓存命中仍可用，但缓存失效后立即故障。
- 异步任务（导入导出）全部失败。

## 3. 快速判断命令

```bash
# 1) PostgreSQL 容器状态
docker ps --filter "name=yutong-postgres" --format "{{.Names}}\t{{.Status}}\t{{.Ports}}"

# 2) TCP 连通性
docker exec yutong-boot sh -c "nc -zv yutong-postgres 5432 2>&1" || echo "POSTGRES UNREACHABLE"

# 3) 凭据验证
docker exec yutong-postgres psql -U yutong -d yutong -c "select version();"

# 4) 连接池状态（应用侧）
curl.exe -s "http://localhost:20010/actuator/metrics/hikaricp.connections.active" | python -m json.tool
curl.exe -s "http://localhost:20010/actuator/metrics/hikaricp.connections.pending" | python -m json.tool

# 5) 活跃连接 SQL
docker exec yutong-postgres psql -U yutong -d yutong -c "
select state, count(*)
from pg_stat_activity
where datname = current_database()
group by state;"

# 6) 长事务 TOP 20
docker exec yutong-postgres psql -U yutong -d yutong -c "
select pid, usename, application_name, state,
       now() - query_start as duration,
       left(query, 200) as sql
from pg_stat_activity
where datname = current_database()
order by duration desc
limit 20;"

# 7) Flyway 状态
docker exec yutong-postgres psql -U yutong -d yutong -c "
select installed_rank, version, description, success, installed_on
from flyway_schema_history
order by installed_rank desc
limit 10;"
```

## 4. 关键日志位置

| 位置 | 内容 |
| --- | --- |
| `docker logs yutong-postgres` | PG 启动、FATAL、磁盘空间 |
| `docker logs yutong-boot` | HikariCP、Flyway、DataSource 异常 |
| PostgreSQL `pg_stat_activity` | 活跃连接、长事务 |
| `flyway_schema_history` 表 | 迁移历史与失败记录 |

## 5. 回滚或临时降级方案

### 5.1 数据库前向补偿（首选，DDL 不回退）

> 设计原则: 生产优先向前兼容，避免必须回滚 DDL（见 63 号文档）。

```bash
# 1) 定位失败的 Flyway 迁移
docker exec yutong-postgres psql -U yutong -d yutong -c "
select installed_rank, version, description, success
from flyway_schema_history
where success = false;"

# 2) 修复失败迁移（手动 DDL 补偿）
docker exec yutong-postgres psql -U yutong -d yutong -c "
delete from flyway_schema_history where success = false;"
# 然后修正 SQL 文件后重新启动应用让 Flyway 重跑

# 3) 若 DDL 已部分应用，需手动补偿
docker exec yutong-postgres psql -U yutong -d yutong -f /docker-entrypoint-initdb.d/补偿脚本.sql
```

### 5.2 数据库备份恢复（极端情况）

```bash
# 1) 确认最近备份
ls -lh /backup/postgres/

# 2) 停止应用
docker stop yutong-boot

# 3) 恢复备份
docker exec yutong-postgres psql -U yutong -d postgres -c "drop database yutong;"
docker exec yutong-postgres psql -U yutong -d postgres -c "create database yutong;"
gunzip -c /backup/postgres/yutong_YYYYMMDD.sql.gz | \
  docker exec -i yutong-postgres psql -U yutong -d yutong

# 4) 重启应用
docker start yutong-boot
sleep 30
curl.exe -s http://localhost:20010/actuator/health
```

### 5.3 临时降级（连接池耗尽）

```yaml
# application.yml 紧急调整
spring:
  datasource:
    hikari:
      maximum-pool-size: 40   # 临时扩容（谨慎）
      connection-timeout: 30000
      leak-detection-threshold: 60000
```

```sql
-- 杀死空闲长连接（须 Incident Commander 确认）
select pg_terminate_backend(pid)
from pg_stat_activity
where datname = 'yutong'
  and state = 'idle'
  and now() - state_change > interval '10 minutes';
```
